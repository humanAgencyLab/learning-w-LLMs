# 3 System Overview

The Learning with LLMs platform introduces a novel adaptive learning system designed to support Self-Regulated Learning (SRL) through milestone-based progression and LLM-powered personalized instruction. The system leverages Large Language Models to provide structured, adaptive teaching that responds to individual learner needs while maintaining pedagogical coherence. As illustrated in Figure 1, the system features a structured learning flow: Intent Assessment → Personalized Planning → Milestone-Based Learning → Module Quizzing → Feedback → Completion. The system is designed to measure SRL effectiveness in a research study with 200 participants, requiring careful token budget management (50,000 tokens/day) while maintaining educational quality.

## 3.1 Design Rationale

### 3.1.1 Milestone-Based Progressive Learning

The system adopts a milestone-based learning structure where each module is divided into 3-6 sequential milestones, each representing a specific learning objective. Students must correctly answer an assessment question for each milestone before progressing to the next, creating a structured progression path. This design is grounded in Self-Regulated Learning theory [cite], which emphasizes the importance of clear learning goals, self-monitoring, and adaptive strategy use. By breaking complex topics into manageable milestones, the system supports learners in developing metacognitive awareness of their progress while preventing cognitive overload through microlearning principles [cite].

The milestone structure ensures sequential progression—learners cannot skip foundational concepts, as each milestone builds upon previous ones. When a learner answers incorrectly, the system provides targeted re-explanation and allows one retry before forced progression, balancing learning support with forward momentum. This approach addresses the challenge of maintaining learner engagement while ensuring comprehensive topic coverage. Each milestone teaching follows a uniform structure: introduction/acknowledgment (1-3 sentences), teaching content (150-200 words), and exactly one assessment question, ensuring consistent teaching depth across all milestones.

### 3.1.2 Adaptive Teaching Through LLM-Powered Assessment

The system employs a sophisticated assessment mechanism where each milestone teaching is followed by a formative assessment question. The system uses an LLM-based assessment analyzer to evaluate student responses, distinguishing between four response types: clarification requests (student needs help), wrong answers (student attempted but incorrect), correct answers (student understands), and incomplete answers (correct but brief). This classification enables adaptive teaching responses that are tailored to the learner's current understanding level.

Rather than using keyword matching or simple pattern recognition, the system leverages natural language understanding to interpret student responses contextually. For example, responses like "I don't know" or "I'm confused" are classified as clarification requests and trigger additional explanation, while incorrect but substantive answers trigger re-teaching with alternative explanations. This design aligns with formative assessment principles [cite] that emphasize using assessment to guide instruction rather than merely evaluate learning. The system implements four assessment scenarios: correct answers trigger progression, clarification requests trigger additional explanation, first incorrect attempts trigger re-teaching with retry opportunity, and second incorrect attempts trigger final explanation with forced progression to prevent learning loops.

### 3.1.3 Personalized Learning Plan Generation

Before learning begins, the system generates a personalized learning plan consisting of 2-3 modules (each with 3-6 milestones) based on the learner's profile, goals, and stated learning intent. The plan generation process uses an LLM to analyze the learner's background, strengths, knowledge gaps, and learning preferences to create a coherent learning path. Learners can review and request modifications to the plan before approval, giving them agency in their learning journey while ensuring the plan aligns with their needs.

This personalized planning phase addresses the SRL component of goal setting and strategic planning [cite]. By involving learners in the planning process, the system supports the development of strategic learning skills while ensuring that the generated plan is both comprehensive and aligned with learner expectations. The plan serves as a roadmap that learners can reference throughout their learning journey, supporting self-monitoring and progress tracking.

### 3.1.4 Integrated Quiz Assessment with Adaptive Feedback

After completing all milestones in a module, learners take a 5-question multiple-choice quiz that tests understanding across all module concepts. The quiz questions are generated by an LLM specifically focused on the module's milestones, ensuring alignment between teaching content and assessment. Learners must achieve ≥60% to pass and proceed to the next module. If they fail, the system uses LLM analysis to identify which milestones need review, providing targeted feedback and returning learners to those specific concepts.

The quiz serves as a summative checkpoint that validates milestone-level learning while providing opportunities for remediation. The system's ability to identify specific knowledge gaps through quiz failure analysis enables targeted review rather than requiring learners to repeat entire modules. This design supports the SRL principle of adaptive strategy use, where learners adjust their approach based on performance feedback.

## 3.2 System Architecture

### 3.2.1 Multi-Prompt LLM Architecture

The system implements a multi-prompt LLM architecture where a single LLM instance (Groq API with Llama 3.3 70B) is used with specialized prompt modules that handle distinct responsibilities in the learning flow, as illustrated in Figure 2. The **Intent Analyzer** prompt module processes initial user messages to detect learning intent and trigger assessment. The **Plan Generator** prompt module creates personalized learning plans (2-3 modules) based on learner profiles, goals, and learning preferences. The **Conversation Manager** prompt module orchestrates the learning flow, making decisions about phase transitions, milestone progression, and teaching actions based on conversation context. The **Teacher Prompt** module generates structured teaching content (150-200 words per milestone) with embedded assessment questions following a uniform structure. The **Assessment Analyzer** prompt module evaluates student responses using natural language understanding to determine understanding level and recommend next actions. Finally, the **Quiz Generator** prompt module creates module-specific quizzes (5 questions) aligned with milestone content.

This multi-prompt design enables specialized, high-quality outputs for each system component while maintaining context coherence through structured information exchange. Each prompt module receives relevant context (learner profile, conversation history, current milestone, progress state) and builds specialized prompts for the same LLM instance, creating a seamless learning experience. Using a single LLM instance with different prompts is more token-efficient than separate agent instances while achieving similar specialization. The prompts for each module are provided in Appendix X.

### 3.2.2 Token Optimization for Scalability

Given the research study's token budget constraints (50,000 tokens/day for 200 participants), the system implements several token optimization strategies. **Context Summarization** compresses conversation history every 40 turns, replacing older messages with structured summaries that preserve key learning context while reducing token usage by 60-80%. **Message Windowing** limits conversation history to the last 15 messages, with further truncation to 2000 tokens when needed. **Structured Context Summaries** replace full conversation history with JSON-formatted summaries containing key concepts mastered, misconceptions resolved, and next learning objectives.

These optimizations enable the system to maintain educational quality while operating within strict token budgets, making it feasible to support large-scale research studies. The summarization approach is inspired by Cursor IDE-style context management, where structured summaries preserve essential information while dramatically reducing token consumption. In our study, these optimizations enabled the system to support 200 participants within the daily token limit while maintaining consistent teaching quality.

### 3.2.3 State Management and Progress Tracking

The system maintains comprehensive state tracking through a Session model that records learning phase (pre, assessing, planning, learning, quizzing, feedback, completed), current module and milestone indices, milestone completion status, quiz attempts, and progress metrics (points, gems, progress percentage). This state enables the system to resume learning sessions, track progress across multiple sessions, and provide learners with clear visual feedback on their advancement.

Progress is calculated deterministically based on milestone completion, with points distributed proportionally across modules. The system ensures progress accuracy through recalculation after each milestone completion and quiz submission, preventing inconsistencies that could undermine learner motivation or research data validity.

## 3.3 Implementation

The system's fully automated learning workflow is implemented as a multi-prompt LLM architecture using Groq API (Llama 3.3 70B), as shown in Figure 2. The system uses a single LLM instance with specialized prompt modules that define different roles and responsibilities, enabling context synchronization through shared state management rather than inter-agent communication.

**Learning Flow Implementation.** The learning flow follows a structured state machine: Intent Detection (pre/assessing phase) → Plan Generation (planning phase) → Milestone-Based Learning (learning phase) → Module Quiz (quizzing phase) → Feedback and Module Transition (feedback phase) → Completion (completed phase). Each phase transition is managed by the Conversation Manager LLM, which analyzes context and determines appropriate actions. In the learning phase, the system enforces sequential milestone progression. Each milestone teaching follows a uniform structure: introduction/acknowledgment (1-3 sentences), teaching content (150-200 words), and exactly one assessment question. This uniformity ensures consistent teaching depth while enabling the system to generate high-quality content reliably.

**Adaptive Response Generation.** The system implements four assessment scenarios that trigger different teaching responses. Scenario A (correct answer, milestone achieved) moves to the next milestone with acknowledgment and transition. Scenario B (correct but needs clarification) provides additional teaching content before progression. Scenario C (incorrect first attempt) re-explains the topic with alternative approaches and allows retry. Scenario D (incorrect second attempt) provides final explanation and forces progression to prevent learning loops. When learners answer assessment questions, the Assessment Analyzer uses natural language understanding to determine the response type and triggers appropriate adaptive teaching.

**Technical Infrastructure.** The system is built on a React frontend with Express.js backend, using MongoDB for data persistence. The backend implements comprehensive error handling, input validation, rate limiting (60 requests/minute), and API retry logic with exponential backoff to ensure reliability. The frontend uses Zustand for state management, providing real-time UI updates that reflect learning progress, milestone completion, and phase transitions. Security measures include JWT-based authentication, input sanitization, and structured error responses.

**Adaptability of Implementation.** In our system, all content is generated by Llama 3.3 70B since it is competent across the topics we chose (Python programming, Guitar, Piano). However, as the multi-agent system and prompts are not topic-specific, we assume that simply modifying the topic indicator in prompts can adapt the system to more contexts, as long as the LLM is competent in that area or supplemented with external knowledge through techniques such as RAG [cite].
